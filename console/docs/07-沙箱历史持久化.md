# 沙箱申请历史（方案 A，共用 PostgreSQL）

Console BFF 在 **与 OpenSandbox Server 相同的数据库**（如 `opensandbox`）中维护独立表 **`console_sandbox_history`**，不修改 Server 源码。

## Server 库里已有什么

| 表 | 归属 | 内容 |
|----|------|------|
| `snapshots` | Server | 快照元数据（可读：`source_sandbox_id` 关联沙箱） |
| `templates` | Server | FastSandbox 模板目录 |
| `console_sandbox_history` | **Console BFF** | 经 Console 创建/同步的沙箱申请与运行时长 |

Server **不**持久化「沙箱列表历史」；K8s 模式下 list 来自现网工作负载，删除后 API 即无记录。历史表补的是 **Console 视角**。

## 启用

环境变量（见 [02-BFF配置与Secret.md](./02-BFF配置与Secret.md)）：

| 变量 | 说明 |
|------|------|
| `BFF_HISTORY_ENABLED` | `true` |
| `BFF_HISTORY_DATABASE_URL` | 与 `values-public.yaml` 中 `[store.postgresql].dsn` **同库**即可（账号需能 CREATE TABLE + 读写 `console_sandbox_history`；读 `snapshots` 可选，用于历史页「快照数」） |

BFF 启动时自动 `CREATE TABLE IF NOT EXISTS`。

部署示例：`build/opensandbox-new-charts/console/console-bff.yaml`（DSN 放 Secret，勿提交真实密码）。

## 写入时机

- 租户/Admin 经 Console **创建**沙箱 → 插入/更新
- **列表/详情**拉取 Lifecycle → 同步状态与 `wall_clock_seconds`
- **删除**（Console）→ 历史行强制 `Terminated`，并写 `deleted_at` / `ended_at`
- **打开申请历史 / 概览统计 / 用量分摊**时默认与 Lifecycle 列表对账（`reconcile=true`，可 `?reconcile=false` 关闭）：
  - 将各租户 **当前 Lifecycle 列表中的沙箱** upsert 进 `console_sandbox_history`（`source=lifecycle-reconcile`），含 SDK/curl 直连创建、尚未经 Console 页面触发的实例
  - 已不在列表中的「进行中」历史行标记为 `Terminated`（过期、删除等）
- 对账最多拉取每租户 **10×200** 条现网沙箱；超出页数的实例需经 Console 列表/详情或调大对账逻辑后再同步

**从未出现在 Lifecycle 列表中**（例如启用历史前已创建并销毁）的沙箱 **无法** 回填。

## API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/history/sandboxes` | 分页历史；Admin 可用 `?tenant=`；可选 `from`+`to`（与用量分摊同一生命周期交集口径） |
| GET | `/api/history/sandboxes/{sandboxId}` | 单条历史（已销毁沙箱详情回退）；Admin 需 `?tenant=` |
| GET | `/api/history/stats` | 条数、累计/平均运行时长 |
| GET | `/api/history/usage?from=&to=` | 区间内租户用量与占比（limits 口径） |

前端：**申请历史**（`/history/sandboxes`）、**用量分摊**（`/history/usage`）。

### 用量分摊公式

运维向完整说明（含综合占比策略）：[`build/opensandbox-new-charts/console/用量分摊-计算公式与策略.md`](../../build/opensandbox-new-charts/console/用量分摊-计算公式与策略.md)。

- 统计窗口：`[from, to)`（RFC3339 UTC）。
- 每条历史记录取 `lifecycle_created_at`（或 `first_recorded_at`）为开始；结束为 `ended_at` / `deleted_at`，仍在运行的沙箱截到 `min(now, to)`。
- **占用秒数** = 与窗口的交集时长之和；单沙箱结束时刻取 `ended_at` / `deleted_at`，或已终止记录冻结的 `wall_clock_seconds`，**不会**把已销毁沙箱延续到 `now`（打开用量页会先与 Lifecycle 对账）。
- **CPU·秒** = Σ `cpu_cores × 占用秒`；**内存·Gi·秒** = Σ `memory_gi × 占用秒`。
- `cpu_cores` / `memory_gi` 来自创建时的 `resourceLimits`（写入 `create_request` 或同步字段）；缺失时默认 `cpu=1`、`memory=512Mi`。
- 各租户 **分项占比** = 该租户指标 ÷ 窗口内全部 Console 历史沙箱合计 × 100%（时长 / CPU / 内存各算各的）。
- **综合分摊占比**（Console 默认）：  
  `composite_i = (T_i/T_tot + C_i/C_tot + M_i/M_tot) / k × 100%`  
  其中 `T` 为占用秒，`C` 为 CPU·秒，`M` 为内存·Gi·秒，`k` 为分母大于 0 的维度个数（通常为 3）。即对三项 **占比** 做 **等权平均**；所有租户的 composite 之和为 100%。  
  若将来有内部单价，可改为 `α·T占比 + β·C占比 + γ·M占比` 或按 `核时×单价 + Gi时×单价` 归一化。

仅包含 `console_sandbox_history` 中已有记录（含 Lifecycle 对账 upsert 的 SDK 现网沙箱）。

## 权限建议

- **简单**：BFF 使用与 Server 相同的 `opensandbox` 数据库用户（你们现网 DSN）。
- **收紧**：单独用户 + `GRANT SELECT, INSERT, UPDATE ON console_sandbox_history`；若需快照数列再加 `GRANT SELECT ON snapshots`。
